# 同步歌词、译文与独立开关修正

## 本次纠正

- 用户确认“没有时间数字，但滚轮能翻阅”。这是纯文本歌词分支，原先没有独立常显的歌词类型提示，容易误认为播放器进度失效。本轮公开接口诊断还观察到 LRCLIB 返回 HTTP503，网易云同一歌曲有37条时间行及35条原始译文行。
- 原先把“开启歌词”与阅读模式绑定是需求理解错误：现在只在中央底部显示歌词框，不切换编辑/阅读状态、不触发保存，也不要求先选文章。编辑模式的右侧图片照常保留；仅阅读模式下，底部歌词和照片板占同一位置。
- 顶部音乐按钮选中后用主题强调底色和明暗反差图标，选中/取消及切换主题时刷新，避免图标与底色糊成一块。旁边四项下拉设置保留，歌词框无控制按钮。

## 数据来源和显示

新增 `services/netease_lyrics.py`，仅用当前歌曲名/歌手搜索网易云公开网页接口，按标题、歌手、时长±2秒筛选，优先相同专辑，最多尝试两个候选。不登录、不读Cookie或客户端数据库。获取 `/api/song/lyric` 的 `lrc.lyric` 与 `tlyric.lyric`；公开网页接口不承诺长期稳定。

优先网易云带时间轴的歌词及译文；匹配不到或接口失败时退回LRCLIB。LRCLIB签名接口只返回纯文本时，会继续搜索同曲的同步版本，最后才保留纯文本。所有请求仍可取消，切歌淘汰旧请求，仅内存缓存。

新增 `services/lyric_data.py` 统一LRC解析。译文按时间戳与原文对齐（误差最多0.5秒），不按行号硬配，不用AI补写。当前行原文和较小字号译文上下显示，前后行显示原文。无译文明确显示“暂无译文”；只有纯文本时标注“无时间轴，无法自动换行”。

播放时钟独立固定在右上角，不再因纯文本或长歌名而消失；歌词来源及同步/纯文本状态单独显示。正常滚轮仅用于纯文本翻阅，不能把它视为自动同步。

## 本轮验证

- 先发现直接接口能取得时间轴/译文，旧LRCLIB服务503；初次Qt入口检查未匹配，不记为通过。
- 最后使用临时数据库、实际界面按钮和真实网易云当前歌曲链路检查：保持编辑模式，获取43条时间行、33条成功对齐译文，实际进度208.165→209.997秒，定位索引40，界面刷新timer有效。没有输出歌词或私人日记。仅做针对性启动/故障检查，不跑全量测试。
- 虚构双语界面预览单独保存，不含真实日记或实际歌词。用户需重启整个脚本版进程，独立EXE未重打包。

网易云来源为 `https://music.163.com/api/search/get` 与 `https://music.163.com/api/song/lyric`。LRCLIB说明：https://lrclib.net/docs 。此前修好的免插件进度读取保留，不安装BetterNCM/InfLink-rs。
