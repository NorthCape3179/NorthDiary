# 人物档案（v1.5）

## 操作

- 左侧“人物档案”：搜索姓名/代号，卡片为默认圆形剪影头像、姓名和代号；支持新增。点击卡片在同一弹窗切换详情，可返回列表。
- 详情自上而下：头像、姓名、代号、出生年月日、相遇时间、相遇方式、相关事件。相关事件只显示带此人物标签且未在回收站的文章，双击打开只读回忆。
- 底部依次为编辑、删除、置顶、星标，可取消置顶/星标。置顶人物排在列表前；星标在卡片与详情右上角显示星星，两状态互不代替。
- 右侧“人物标签”选择当前文章的人物，点击卡片切换主题色图标；底部两行无限列显示已选人物，滚轮横向移动，× 取消。确认后保存关联，取消则放弃本次选择。搜索不清除已选人物。
- 旁边箭头展开/收起最右侧两列无限行的快捷区。按钮只显示姓名与代号，纵向滚动；点击将代号以纯文字插入正文当前光标处，可撤销，不自动添加人物标签。
- 阅读模式、未选文章时禁用文章标签与快捷插入；左侧档案仍可浏览。打开弹窗前先保存当前文章，失败停止打开并保留编辑。人物编辑保存失败保留已填内容。

## 数据规则

人物编号稳定，姓名可重复，代号必填且唯一（区分大小写）。姓名和代号各最多 100 字，相遇方式最多 10000 字；日期可留空、写年份、年月或完整日期，也支持 YYYY-未知-未知 / YYYY-MM-未知，日期必须有效。当前头像仅程序绘制的默认剪影，未提供自定义头像。

人物保存在 people 表，文章标签保存在 article_people 关系表，同一人物可关联多篇文章，一篇可关联多个人物。文章与人物标签共同提交，失败回滚。修改姓名/代号保留关联，正文已插入的代号文字不会自动替换。删除人物需确认，只删除档案和关联，不删文章、不改正文。

SQLite schema 从 v3 升级到 v4。原有 v3 库首次打开前会在数据目录 backups 保存 before-v4-*.sqlite3，之后事务迁移；失败回滚并停止打开。原来的文章、标签、附件不移动。已有 v1/v2 库沿用旧迁移备份并继续升级。备份导出包含整个数据库，所以包含全部人物档案（即使没有关联文章）。

**旧程序不能打开升级后的数据库。** 保留旧源码不等于数据库能直接降级；回退使用升级前快照的副本和对应附件目录，勿覆盖正在使用的数据。恢复界面仍未实现。

## EPUB 与 GitHub 交换

原生清单升到 v2，正常 EPUB 阅读正文不变。只携带所选文章关联的人物资料（含置顶、星标），不导出没有关联到所选文章的人物。原生清单内包含人物出生日期、相遇资料，分享前应知悉这些信息随包携带。

新程序兼容读取 v1 原生包（没有人物数据）；旧程序拒绝 v2 包，避免静默丢掉关联。GitHub 预检兼容 v1/v2，上传/下载仍使用文章包，无新增网络服务、权限或依赖。

同编号且资料相同的人物复用；编号冲突或代号已占用时保留本机人物、生成有稳定导入编号的副本。代号冲突追加“（导入-编号）”后缀。文章关联导入后的正确人物，不覆盖本机档案；导入副本的正文原有代号文字保持原样，不自动改字。重复文章包仍按原有指纹规则跳过；不同人物资料版本可能使文章被视为不同内容而产生副本，不做自动合并。导入校验整本人物编号、代号与资料一致性，任何写入失败一起回滚。
